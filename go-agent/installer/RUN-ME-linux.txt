CSPC-ICTU SERVER MONITORING AGENT  —  Linux install
===================================================

Copy OR download this WHOLE folder to the Linux server you want to monitor.
(Downloaded from Google Drive/email? No special unblock needed on Linux — the
 "chmod +x" in Option A step 1 restores the binary's execute permission.)

WHAT'S IN HERE
  go-agent-linux-amd64    agent binary for Intel/AMD (x86_64) servers
  go-agent-linux-arm64    agent binary for ARM (e.g. Raspberry Pi)   
  install.sh              installs it as a systemd service (runs at boot)
  RUN-ME.txt              this file

WHAT THIS AGENT REPORTS
  CPU, memory, uptime and process count, plus:
    - EVERY mounted fixed filesystem (/, /home, /data, ...), not just the root
      one. A data partition filling up while / looks healthy is the usual real
      incident. Pseudo filesystems (tmpfs, overlay, squashfs) are ignored.
    - Its own details (IP, RAM, disk size), re-sent hourly, so the dashboard
      stays right after a network or hardware change.
  If the backend goes down it KEEPS the readings it couldn't send (about 40
  minutes' worth) and fills them in once the backend is back — so an outage
  leaves a gap in the live view, but not in the stored history.

  Pick the binary that matches your CPU:
     run:  uname -m
        x86_64   -> use  go-agent-linux-amd64
        aarch64  -> use  go-agent-linux-arm64

BEFORE YOU START
  - The backend PC must be ON and on the SAME network as this server.
  - Backend address:  http://192.168.100.9:3000
  - Test it FIRST:    curl http://192.168.100.9:3000
       You should see:  {"error":"Route not found"}
       If it fails -> wrong network, or the firewall on the backend PC is blocking 3000.

-----------------------------------------------------------------------
OPTION A  —  QUICK TEST  (run by hand so you can watch the logs)
-----------------------------------------------------------------------
  (example uses the amd64 binary; swap to arm64 if "uname -m" says aarch64)

  1) chmod +x go-agent-linux-amd64

  2) Enroll (registers, then waits for approval):
       ./go-agent-linux-amd64 --register -api-url http://192.168.100.9:3000 -install-key "<AGENT_INSTALL_KEY>" -conf agent.conf
     -> prints "waiting for admin approval..." and keeps checking.

  3) On the backend dashboard, logged in as an ADMIN:
       Server Metrics -> refresh -> "Pending agent approvals" -> APPROVE this server.

     That's it - NO second command. After you approve, the SAME process keeps
     running and starts sending metrics automatically:
     "metrics sent (cpu=.. mem=.. disk=..)" every 10 seconds; server appears LIVE.
     Leave it running (or use Option B for a boot service).

  (To run it again later, once already enrolled:  ./go-agent-linux-amd64 -conf agent.conf )

-----------------------------------------------------------------------
OPTION B  —  PERMANENT INSTALL  (systemd service, starts at boot)
-----------------------------------------------------------------------
  Do this only after Option A worked. install.sh auto-picks amd64/arm64.

       sudo bash install.sh http://192.168.100.9:3000 <AGENT_INSTALL_KEY>

  Then approve it in the dashboard (same as Option A, step 3).
  Check status:   systemctl status cspc-agent

-----------------------------------------------------------------------
ALREADY HAVE AN OLDER AGENT ON THIS SERVER?  —  UPGRADING
-----------------------------------------------------------------------
  Do NOT re-register. The server keeps its existing enrolment and approval; you
  are only swapping the program file.

  Symptom you are fixing: the dashboard shows the server fine, but its "Volumes"
  panel says "No volume data yet". That means an OLDER program is still running —
  it cannot send what it doesn't collect.

  (The version number does not help you here: pre-release builds all report 1.0.0,
   so the Volumes panel is the reliable way to tell old from new.)

       sudo systemctl stop cspc-agent
       sudo bash install.sh http://192.168.100.9:3000 <AGENT_INSTALL_KEY>

  install.sh skips enrolment when agent.conf already exists, so nothing needs
  approving again.

  Confirm:  systemctl status cspc-agent      (should be active/running)
  Then on the dashboard the Volumes panel fills in within about 10 seconds,
  listing every mounted filesystem on this server.

-----------------------------------------------------------------------
TROUBLESHOOTING
-----------------------------------------------------------------------
  "Invalid install key"      -> key here must match AGENT_INSTALL_KEY in backend .env
                                (backend must be restarted after that line was added).
  "send attempt 1/3 failed"  -> backend not running, wrong address, or firewall.
  curl test fails            -> not on the same network, or port 3000 blocked.
  server never shows         -> you didn't Approve it, or didn't run step 4.
  "Volumes" panel stays empty -> an OLDER agent is still running. See "UPGRADING"
                                above. (A brand-new install shows mounts in ~10s.)
  server shows "Maintenance" -> an admin parked it on purpose; it keeps recording
                                but won't raise alerts. Click "Resume" on the
                                Server Metrics page.

NOTE: keep this folder private (USB, Google Drive, or email) — the install key is a
      shared secret. If you share it on Google Drive, share to specific people only,
      NOT "Anyone with the link". Never upload an agent.conf file (it holds a device token).
